# 手機版順手度修正（2026-11-18）

使用者：「送出後運行中打字區還留著上一句」「瀏海只要有未回答的問題，其他都不用顯示」「用起來很不順手」。
2026-11-18 用選項問過，六項全做。

## 要做的

1. **送出就清空輸入框**：按送出的當下清空（含草稿），不等筆電回應；送出失敗才把原文放回去。
   中文輸入法還有組字中（marked text）時也要確實清空。
2. **送出後對話底部馬上出現那句**：顯示成自己的訊息、旁邊標「送出中」；筆電的對話紀錄出現同一句（或 15 秒後）就拿掉暫時那則；
   送出失敗就拿掉並把字放回輸入框。
3. **送出後收鍵盤**（不分有沒有題目卡）。
4. **即時狀態（動態島＋鎖定畫面）只在有 session 等你回答時出現**；只有工作中／背景跑時不開、已開的要結束。
   顯示內容只講等你回答的：幾個在等、第一個在問什麼。結束時立刻消失（不再留 15 分鐘）。app 端（`LiveActivityController`、`SharedConfig`）與筆電推播端（`notify.activity_payload`／`_push_activity`）一致。
5. **完工不推播**：預設只有「等你回答」跳通知。設定頁的「完工只推標星號的」換成「完工也推播」（預設關）；打開時才看「只推標星號」。
6. **列表直接回答**：等你回答的卡片底下直接出現選項按鈕，按了等同在對話頁按（同一支 `press`，帶 label 核對）。
   只做單選題與權限提示／計畫核准這類「按一下就送」的；複選題、一次多題的確認頁、只能打字的，顯示「點進去回答」。

## 明確不做

- 不改後端送字流程（`actions.reply` 的時序）、不改題目卡在對話頁的樣子。
- 不做列表上打字回答。
- 不動展示模式以外的假資料情境結構（可以加情境，不改舊的）。

## 驗收

- `cd backend && .venv/bin/pytest` 綠。
- `tools/uitest.sh --sim` 綠，加測：送出後輸入框立刻是空的、對話出現「送出中」那則；列表的等你回答卡片按選項後狀態改變。
- 模擬器截圖目視：列表題目卡、送出中、`SR_ACTIVITY=1` 動態島（只有等你回答時才有）。
- 真機：使用者實際用（我看不到手機）。

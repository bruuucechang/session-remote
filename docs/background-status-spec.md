# 規格：手機上分得出「背景還在跑」與「完工」（2026-11-08）

## 問題

回合一結束 app 就標「做完了」並推播，但很多 session 結束回合時還掛著背景任務
（`run_in_background` 的 Bash、`waitfor --label …`）。手機上分不出哪些其實還在跑、哪些真的完工。

## 使用者裁示

- 完工的判準：**回合結束、而且沒有背景任務**（全自動判定，不用手動確認）。
- 推播：回合結束時還有背景就不推；**背景也全部結束、session 還停著才推一則「完工」**。

## 做什麼

| 項目 | 做法 |
|---|---|
| 新狀態 `background`「背景跑」 | hook 狀態是 done 或 idle、但 claude 程序底下還有 Bash 工具的 shell（命令含 `shell-snapshots/snapshot-`）活著 |
| 在跑什麼 | 每件一行：`waitfor --label X` 顯示 X；其他取指令第一個有意義的行（跳過 `S=…`、`cd …`），截 80 字 |
| `done` 改叫「完工」 | 只剩真的沒背景的；列上時間改成背景結束的時間 |
| 列表 | 新的一區「背景跑」排在「工作中」之後；每列顯示第一件在跑什麼，多件加「等 N 件」 |
| 等你回答＋有背景 | 狀態照舊是等你回答，列上多一個「背景 N」小標 |
| 偵測背景結束 | 筆電每 10 秒只查「上次有背景」的那幾個 pid（`pgrep -P`，不跑 iTerm2 掃描）；沒了就改完工、推播 |
| 鎖定畫面／小工具 | 多一個「背景」數字；有背景跑的時候即時狀態不結束 |

## 明確不做

- 背景 subagent（Agent 工具的背景執行）、Monitor、派到別台機器的工作：不是這台的子程序，偵測不到。
- 不改 working／waiting 的判定；工作中時不顯示背景數（前景指令也是子程序，數字不準）。
- 不加手動「確認完工」按鈕。

## 驗收

- `cd backend && .venv/bin/pytest`：新測試（背景判定、標籤抽取、背景結束推播）各看過紅一次再綠。
- `tools/uitest.sh`：假資料多一個背景跑的 session，列表出現「背景跑」區與它在跑什麼。
- 正式服務 `curl localhost:5391/sessions` 看到這台實際有背景的 session 標成 background。
- 裝到手機。

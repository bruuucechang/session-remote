# 手機 app 大整理：規格（2026-10-25 談定）

## 目標

把 iPhone app 本體的 bug 修乾淨、層級整理好，並留下一套能重跑的自動化 UI 測試，以後改了不會修好又壞。

## 範圍

**做**：app 本體的每一頁——session 列表、對話頁（訊息、回覆輸入框、Esc、關分頁）、
回答題目（單選／複選／多題／確認頁／權限提示／計畫核准／信任資料夾）、開新 session、搜尋、工具詳情、設定、配對。

1. **修 bug＋全面掃**：每一頁、每一種狀態都自動點一遍，找到的一起修。
2. **整理外觀與流程，維持 iOS 原生樣子**：系統清單、字型、深淺色照舊；改的是
   - 第一眼先看到要你處理的 session（等你回答＞做完＞工作中＞待命）
   - 每一頁的空／載入／錯誤／讀失敗狀態做齊，錯誤顯示在出事的那一塊，講壞了什麼＋重試
   - 顏色只用在狀態與唯一的主要動作上；按鈕講按了會發生什麼；送出鈕一定看得到（不被鍵盤蓋住）
   - 點擊目標至少 44pt
3. **自動化 UI 測試留在 repo**（XCUITest，新 target `SessionRemoteUITests`）。

## 怎麼測

| 層 | 對象 | 用途 |
|---|---|---|
| 假資料 | 另起一個測試用後端（`backend` 加假資料模式，不碰 iTerm2），餵固定的 session、對話、各種題目畫面 | XCUITest 平常跑這個，結果固定、能重跑 |
| 測試 session | 我自己在測試資料夾開的 Claude session，用會問題目的第一句話逼出各種狀態 | 實測送字、按選項、Esc、關分頁、提示解析 |
| 真機 | 接著筆電的 iPhone，使用者同意**目前可以一直用**（2026-10-25） | 每一輪修完都在真機跑；模擬器只當補充 |

**自動點只准對測試 session 送字／按鍵／關分頁**；使用者的真 session 只能看，不送任何東西。
測試程式用一個前綴（例如資料夾 `~/Projects/session-remote/.uitest-sandbox`）認出測試 session，碰到別的就失敗退出。

## 驗收

- `xcodebuild test`（真機＋假資料後端）全綠，而且每條回歸測試都親眼看過它紅一次。
- 測試 session 實測：單選、複選、多題確認頁、權限提示、Esc、關分頁、開新 session 帶第一句話，各成功一次。
- 每一頁的每種狀態都有截圖，逐張目視過（app-design 第十節七題的 iOS 版）。
- 後端 `pytest` 全綠。
- 最後真機裝好，請使用者實際用一次。

## 明確不做

- 小工具、鎖定畫面即時狀態、動態島、推播（內容與外觀都不動）。
- 不整套重新設計：不自訂主色、字級系統、對話泡泡樣式。
- 不改後端的分層規則（AGENTS.md「分層規則」）與既有 API 的語意；假資料模式只加不改。
- 不動 SPEC.md「明確不做」那幾條。
- 自動點不碰使用者自己的 session。
